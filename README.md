# CoFlow · 项目事实层（阶段一）

多人 + 多 AI Agent 的项目协作工作台。首版只做一件事：**把项目从创建到验收完整跑通**，
让人和未来的 Agent 读同一份事实，而不是各自电脑上的聊天记录。

设计依据：《多 Agent 团队协同工作台_完整设计方案》V1.0，第 12.3 节「阶段一：事实闭环」。

## 这一版做了什么

| 能力 | 实现位置 | 要点 |
| --- | --- | --- |
| 项目章程 | `/projects/new`、`/projects/[id]/settings` | 目标变更生成新版本，旧版本保留 |
| 成员与角色 | settings | 5 种角色，权限只作用于事实层的写入 |
| 任务看板 | `/projects/[id]/tasks` | 6 列状态 + 阻塞/暂停旁路 |
| 任务状态机 | `src/lib/task-state.ts` | 服务端强制，不可跳级，转换带前置条件 |
| 项目对话 | 工作台中栏 | 讨论与系统事件分开展示 |
| 形成决策 | 消息右侧按钮 | 提案不进入事实层，确认后才算 |
| 产物提交 | 任务详情 / 产物中心 | 完成必须关联产物或明确说明 |
| 人工验收 | 任务详情 `/tasks/[id]` | 标准—证据—结论，只有验收权人能下结论 |
| 事件流 | 所有写操作 | 与业务写入同事务，不可变 |
| 乐观锁 | 任务更新 | 携带版本号，冲突明确拒绝 |
| 事件协议说明 | `/docs/protocol` | 给阶段二 Connector 的契约 |

## 关键规则（不是 UI 约定，是写入规则）

**任务状态机**

```
待澄清 → 待认领 → 已就绪 → 进行中 → 待验收 → 已完成
旁路：已阻塞 / 已暂停 / 已取消
```

- 待澄清 → 待认领：必须有输入材料与验收标准
- 待认领 → 已就绪：必须指定负责人
- 进行中 → 待验收：至少一项产物，或填写无产物说明
- 待验收 → 已完成：只有发起人 / 负责人 / 评审可以
- 已完成 → 进行中：返工，`revision + 1`，原验收记录保留

**事实与聊天分离**：消息不会改任务状态；决策必须经「确认」才进入事实层。

**进度**：只由验收状态与任务权重计算，Agent 自报进度不参与。

## 阶段三进度（异构协作）

| 里程碑 | 内容 | 状态 |
| --- | --- | --- |
| 3.1 | 工具适配器：claude-code / mock-agent / generic | ✅ |
| 3.2 | 工作声明、软锁与独占锁 | ✅ |
| 3.3 | 多设备并发与冲突处理 | ✅ 已验证 |
| 3.4 | 派发推荐（可解释评分） | ✅ |

**为什么只做推荐，不做自动派发**：自动调度需要真实负载才能验证，否则就是拿噪音当信号。
现在系统会给出排序和若干条理由（能力等级、是否空闲、授权目录是否覆盖任务范围、
与执行中会话的路径冲突、近 30 天成功率），人看完再点。理由可以逐条被质疑——
这是它和「黑箱推荐」的区别。等真实项目跑出数据，再谈自动。

**适配器**（`connector/src/adapters.mjs`）把「工具差异」压缩成三个方法：能不能装、怎么调用、输出怎么解析。
租约、上下文、证据、越界检查对所有工具完全一致——换成任何读 stdin 的命令行工具，接入方式不变。

**工作声明**在领取租约时提交，服务端比对该项目下其它 ACTIVE 会话：

- 声明 `prisma/schema.prisma`、`package.json`、迁移目录等 → **独占**，重叠直接 409 拒绝
- 声明普通代码目录 → **软锁**，允许并行但双方都看到重叠提示
- 不声明 → **自由**

项目工作台右侧会列出所有正在执行的会话及其声明的路径。

后续里程碑的要点：

1. 本地 Connector：出站连接、目录白名单、零密钥识别本机 Agent 工具
2. 任务上下文包：`L0 章程 / L1 任务 / L2 动态 / L3 证据` 的组装与预算裁剪
3. Agent 会话与心跳：`agent.session_started / heartbeat / session_ended`
4. 任务租约：有时效、可撤销、绑定上下文版本
5. 工作声明与锁：先做路径声明 + 冲突提示，独占锁放阶段三

## 运维

```bash
pnpm db:deploy     # 部署环境应用迁移（只应用不生成）
pnpm db:status     # 检查数据库是否落后于迁移
pnpm db:prune      # 数据保留预演：可清理的事件与快照
pnpm test          # 8 套单元测试
```

- **健康检查**：`GET /api/health`，数据库不通时返回 503，可直接给反向代理做探活。
- **数据库迁移**：结构变更一律走 `prisma migrate dev`，不要再用 `db push`。
- **数据保留**：`pnpm db:prune --days=30 --apply` 清理过程事件与未被引用的旧上下文快照；决策、产物、验收、状态变更不清理。
- **账号安全**：`/account` 列出登录会话与已接入设备，可单条撤销或一键退出其他设备。
- **可靠性分析**：`docs/reliability.md`，写清了将来会坏在哪里、哪些做了、哪些刻意不做。

## 上手与复盘

两个页面服务于同一件事：让这套系统被验证，而不是被演示。

**`/start` — 15 分钟上手**

五步：建项目 → 连设备 → 授权目录 → 有已就绪任务 → 跑通一次交付。

每一步的完成状态都来自数据库，不是教程里的勾选框。判定刻意收窄到「与你相关」：
旁观者不会因为项目里别人完成了任务就显示「已跑通交付」。

**`/review` — 这一周发生了什么**

| 指标 | 口径 |
| --- | --- |
| 完成 | 本周内出现过 PASS 验收的任务数（同一任务多次通过只算一次） |
| 通过率 | PASS / 全部验收结论 |
| 周期 | 任务创建 → 首次 PASS，取中位数 |
| Agent 会话 | 提交 / 失败 / 进行中，失败按原因聚合 |
| 上下文成本 | 快照 tokens 的均值与最大值 |

七日活动条用两张单系列图，同一色系的深浅两阶；不把主色和辅色当分类色使用
（两者在正常视力下 ΔE 13.1，低于 15 的可分辨下限）。
叙述文字由数字生成，没有活动时就说没有活动。

## 项目模板

创建项目时可选模板，把章程与第一批任务一次带进来：

| 模板 | 内容 |
| --- | --- |
| 软件小团队 | 数据模型 → 骨架 → 服务端 → 客户端 → 联调 → 交付，6 任务 3 里程碑 |
| 内容创作 | 资料 → 大纲 → 初稿 → 视觉 → 校对 → 发布物料 |
| 竞赛项目 | 评分点映射 → 方案 → 实现 → 包装 → 作品书 → 答辩 |

模板只预填定义：生成的任务停在「待认领」，负责人与就绪状态仍由人推进。
数据在 `src/lib/templates.ts`，完整性由 `scripts/templates-test.ts` 保障（依赖索引、无环、验收标准非空）。

## 风险提醒

项目工作台右栏按确定性规则列出风险，规则对所有人一致：

| 规则 | 阈值 | 级别 |
| --- | --- | --- |
| 逾期 | 到期日已过；逾期 2 天以上升为高 | 中 / 高 |
| 阻塞停滞 | 阻塞超过 3 天 | 高 |
| 待验收堆积 | 超过 2 天；5 天以上升为高 | 中 / 高 |
| 进行中无更新 | 超过 5 天 | 中 |
| 待澄清 | 超过 3 天仍缺输入或验收标准 | 低 |
| 依赖已满足 | 前置任务全部完成 | 低（正向提醒） |

逻辑在 `src/lib/risks.ts`，纯函数、可单测（`scripts/risks-test.ts`，19 项）。
不用模型判断「哪里有问题」——那种提醒新鲜两次就没人看了。

## 身份与登录

邮箱验证码登录。会话存库：Cookie 里只放不透明 token，数据库只存 `sha256(token)`，泄库不等于泄会话。

- **开发环境**：没配 SMTP 时验证码直接显示在登录页；顶栏有 `DEV` 身份切换，生产构建不渲染
- **生产环境**：必须配置 `SMTP_*`，否则登录直接报错——不会出现「点了发送但永远收不到」
- 首次登录的邮箱自动建号（昵称取邮箱前缀），之后在项目设置里分配角色
- 验证码 10 分钟过期、一次性、最多 5 次尝试；同邮箱 60 秒冷却、每小时 5 次上限

## 已知边界

- 没有注册/找回密码/多设备管理（设备管理在阶段二 2.1）
- 没有文件上传，产物用「可定位的引用」（提交号 / 路径 / 链接）
- 阶段切换、角色调整写入了事件，但没有审批流
- 登录没有图形验证码，只靠频率限制防刷
