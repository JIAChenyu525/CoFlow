沿用已确认的视觉体系与组件库。这一轮做三页：**项目大厅、新建项目向导、项目设置**。

## 一、项目大厅（首页）

目的：一眼看到所有项目状态，进入某个项目。

内容：
- 标题「项目大厅」+ 一句说明「同一份事实，给人看，也给 Agent 读。」
- 四个统计数字：项目总数、进行中任务数、待验收数、阻塞数
- 项目卡片列表，每张包含：项目代号（如 ZX）、阶段（定义/开发/联调/验收/归档）、项目名称、目标摘要（两行）、交付进度百分比与进度条、状态计数（进行中 / 待验收 / 阻塞）、成员头像组、最近活动时间
- 一张「＋ 新建项目」入口卡
- 页面底部一段产品说明：标题「聊天负责交流意图，任务与产物负责表达事实」，配四个要点：目标（带版本号，变更需分析影响）、任务（状态机驱动，不可跳级）、决策（确认后才进入上下文）、产物（完成必须有证据）

状态：
- 空：没有任何项目，引导创建第一个项目，文案「先建一个项目章程：目标、范围、非目标、约束、验收标准。没有这些，Agent 拿到的上下文只会是一堆聊天记录。」
- 未完成上手时：顶部一条引导条「15 分钟跑通第一个闭环 · 建项目 → 连设备 → 授权目录 → 建任务 → 交付验收」，带「开始 →」

## 二、新建项目（5 步向导）

目的：把想法变成结构化的章程和第一批任务。

第 1 步 · 基本信息
- **模板选择**（放在最上面）：四张可点选卡片——空白项目、软件小团队（6 个任务）、内容创作（6 个任务）、竞赛项目（6 个任务）。每张显示名称、一句描述、任务数量。说明文字："只预填章程与任务清单，之后随便改"
- 项目名称、项目代号（2–6 位大写字母或数字）、一句话说明

第 2 步 · 目标与范围：项目目标、目标用户、交付范围、非目标、硬性约束

第 3 步 · 验收标准：验收标准（多行）；若选了模板，显示一条模板说明（将生成哪些里程碑和任务）替代"首个里程碑"输入；否则显示"首个里程碑"输入

第 4 步 · 成员与角色：
- 发起人固定为当前用户（显示权限说明：目标决策权 + 最终验收权）
- 可勾选成员列表（头像、姓名、账号），勾选后出现角色下拉：负责人 / 成员 / 评审 / 观察员
- 底部一句："角色决定的是事实层的写入权限，不是头衔。"

第 5 步 · Agent 接入：
- 零密钥接入说明：工具授权归原工具、项目授权归 CoFlow
- "本次创建将写入"清单：项目、章程、成员、模板、事件
- 「创建项目」按钮

状态：当前步骤未填完时"下一步"不可点；创建中；失败显示原因；已完成步骤显示勾选。

## 三、项目设置

内容分四块：
1. **项目信息**：名称、代号、当前阶段（下拉 + 应用按钮）
2. **项目章程**：当前版本的全部字段；版本历史（版本号、变更说明、时间）；「修订章程」入口——展开后是完整表单 + 一句必填的"本次变更说明"，保存后生成新版本
3. **成员与角色**：每行头像、姓名、账号、角色说明、角色下拉（仅发起人可改；自己的角色不可改）
4. **数据与保留策略**：六条说明卡片——事件流全量保留；详细 Agent 日志短保留；关键决策与验收长期保留；敏感本地路径不进入事件与归档；模型 API Key 平台不读取、不保存；云端与本地删除分开授权

状态：非发起人看到的是只读的角色展示。
