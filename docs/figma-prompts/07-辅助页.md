沿用已确认的视觉体系与组件库。这一轮做四页：**登录、周报、上手、事件协议**。

## 一、登录

内容：
- 品牌名 CoFlow + 一句定位「项目事实层」
- 标题「登录 CoFlow」，说明「用邮箱验证码登录。项目数据属于你的账号，不属于某台电脑；之后接入 Agent 的设备凭据会绑定到这个账号上。」
- 第一步：邮箱输入 + 「发送验证码」
- 第二步：6 位验证码输入（等宽、大字距）+ 「登录」；上方显示"已发送到 xxx@xxx"；「换个邮箱」入口
- 底部：「继续即表示同意：平台只保存项目事实，不读取、不保存你本地工具的模型密钥。」+ 次要入口「了解事件协议」

状态：发送中；60 秒冷却；验证码错误；已过期。

## 二、周报（这一周发生了什么）

内容：
- 标题 + 日期区间（如 2026-11-06 → 2026-11-12）+ 一句「只统计已经发生的事实，不做预测」
- 右上「15 分钟上手」入口
- **叙述区**：4–6 条由数字生成的事实句，例如：
  - 本周在 1 个项目里新建 5 个任务、完成 2 个。
  - 验收 2 次，全部通过。
  - Agent 会话 3 次：提交 3、失败 0、进行中 0。
  - 从建任务到通过验收，周期中位数 3.7 天。
  - 上下文包平均 869 tokens（最大 899）。这是每次派发的固定成本。
  - 仍有 1 个任务处于阻塞。
- **五个指标**：完成、新建、通过率（含"共 N 次验收"）、Agent 会话（含失败数）、上下文成本（平均 tokens）
- **两张七日图表**：每天新建的任务数、每天通过验收的任务数。同一度量按天展示，单系列。
- **按项目表格**：项目、新建、完成、退回、完成率
- **两张小卡**：卡住的地方（阻塞任务 + 所需支持）、Agent 失败原因（超时 / 越界修改 / 输出无法解析 / Agent 报错）

状态：完全没有活动时——"这一周没有任何项目活动。要么还没开始，要么事情停在了别处。"+ 指向上手页。

## 三、上手（15 分钟跑通第一个闭环）

内容：
- 标题 + 说明「五步。每步的完成状态来自系统真实数据，不是教程里的打勾。」+ 进度（如 3 / 5）+ 进度条
- **五个步骤卡**，每张包含：序号圆圈（完成显示 ✓ 且标题划掉）、标题、时长标签（如"3 分钟"）、说明、「为什么：……」一行弱化文字、命令行代码块 + 复制按钮、动作按钮
  1. 建一个项目（3 分钟）
  2. 连接一台设备（3 分钟，命令 `npx coflow-connector login`）
  3. 给端点授权目录（2 分钟）
  4. 有一个「已就绪」的任务（3 分钟）
  5. 跑通一次完整交付（4 分钟，命令 `coflow pull` 或 `coflow run`）
- **完成态**：全部完成时顶部显示绿色完成提示「闭环已经跑通」+ 一段说明 + 「看这一周发生了什么」按钮
- **未完成态**：顶部一条「下一步 · 连接一台设备 · 约 3 分钟 · 去配对」引导条
- 底部「如果卡住了」三条：
  - 连接器连不上：先跑 `coflow doctor`，它会告诉你缺什么能力
  - 任务移不到「已就绪」：说明输入材料或验收标准还空着
  - 派发按钮不出现：任务必须先是「已就绪」，且项目里要有可用端点

注意：完成状态是系统判定的，视觉上要让人看出来"这不是我自己勾的"。

## 四、事件协议（说明页）

偏阅读型页面，内容以文字和表格为主：
- 原则四条（事件不可变、状态可投影、写入带版本、证据先于结论）
- 事件公共字段表（13 个字段：event_id / project_id / actor_type / session_id / event_type / occurred_at 等）
- 首版事件类型清单（12 个）
- 一段示例 JSON（深色代码块）
- 上下文包分层表（L0–L3，含更新策略）
- Agent 回传合同（7 条）
- 实现偏差说明（设计与实现不一致的地方）

状态：无需交互状态，但要保证长文可读。
