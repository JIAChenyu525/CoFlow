沿用已确认的视觉体系与组件库。这一轮做**三个移动端页面**，尺寸 390×844，iOS/Android 通用，中文界面。

移动端不是桌面端的缩小版，需要重新组织信息。核心原则：**手机上的第一问题是"今天需要我做什么"**，不是"看全局"。

## 一、工作台（移动端）

- 顶部：项目代号 + 项目名 + 交付进度百分比
- 一条横向可滚动的项目内导航：工作台 / 任务与分工 / 产物与验收 / 决策与时间线 / 项目设置
- 主要内容：项目频道消息流（同桌面端的消息类型区分：普通讨论、系统事件、决策提案、产物提交、阻塞、Agent 汇报）
- 底部固定输入框
- 建议：把桌面端右栏的「风险 / 需要处理」做成一个可从顶部滑出的面板或角标入口，而不是全塞进消息流

## 二、任务看板（移动端）

- 顶部：项目代号 + 项目名
- 横向滚动的列表（不是六列并排）：每次露出 1.5–2 列，提示可以左右滑
- 列头：状态名 + 数量；列内是任务卡
- 任务卡：优先级、截止日、标题、负责人头像、产物数/依赖数
- 顶部或底部提供状态切换（如分段控件），让用户快速跳到某一列

## 三、任务详情（移动端）

- 顶部：返回、状态徽标、优先级
- 标题
- 元信息：负责人、验收人、截止、权重（可折行）
- 任务定义：说明、输入材料、工作范围、非工作范围、验收标准
- 产物与证据列表
- 验收记录
- 底部固定操作区：当前状态可执行的主要动作（如"提交验收"/"去验收"），其余动作收进「更多」

## 要求

- 触控目标不小于 44×44
- 长文本不能溢出，代码/路径要能换行或横向滚动
- 三个页面要体现同一套组件（状态徽标、优先级、卡片、空状态）在窄屏下的形态
- 空状态在移动端要更简短
