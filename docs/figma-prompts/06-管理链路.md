沿用已确认的视觉体系与组件库。这一轮做三页：**Agent 连接、产物与验收、决策与时间线**。

## 一、Agent 连接

目的：把成员电脑上的 AI 工具接进来，并管理权限。

内容：
- **「连接一台设备」**：三步说明（1 在目标电脑执行 `npx coflow-connector login` → 2 终端显示形如 `ABCD-2345` 的配对码 → 3 在下方输入）+ 配对码输入框（等宽、大字距）+「授权这台设备」按钮
- **「两层授权，别混在一起」**：两块说明
  - 工具授权 · 归原工具：Claude Code 登录没登录、用哪个模型，平台不碰
  - 项目授权 · 归 CoFlow：能进哪个项目、读哪些任务、写哪些目录、回传哪些事件
- **设备列表**：每台设备一行——设备名、系统、在线状态、配对时间、「撤销」按钮
  - 设备下面是若干 **Agent 端点**，每个端点显示：工具名与版本、能力等级徽标（自动接入 / 半自动 / 手动）、能力说明、绑定项目、最后心跳
  - 半自动 / 手动端点必须显示**降级原因**，例如"该版本不支持无头 JSON 输出（缺少 --print / --output-format）"，并补充"只能半自动或手动执行，不能 coflow run"
  - 端点上有「授权目录」操作：展开为一行输入（多个路径用逗号分隔）+ 保存
- **已撤销设备**区：设备名 + 撤销时间

状态：没有任何设备（引导文案："没有设备也能用完整流程——产物可以用人工回传"）；配对码错误 / 过期 / 已使用；保存目录失败。

## 二、产物与验收

目的：集中处理待验收任务，并查看所有产物。

内容：
- **待验收区**：每个任务一张卡，内部三栏
  - 标准：逐条验收条件（编号列出）
  - 证据：产物列表（类型标签、名称、位置、版本）
  - 结论：显示"尚未验收"+「去验收」按钮
- **已完成区**：任务名、产物数、验收次数、最后验收时间
- **产物清单**：表格——类型、名称、位置（等宽）、版本、来源任务、提交人、时间

状态：没有待验收 / 没有已完成 / 没有产物 的三种空状态。

## 三、决策与时间线

目的：回答「为什么这样做」和「历史上发生了什么」。

内容：
- **决策列表**（按状态排序：提案 → 已确认 → 已被替代）
  每张决策卡包含：状态徽标、标题、结论、理由、备选方案、影响范围、决策人、时间、版本号；若替代了旧决策，显示"取代「旧决策标题」"
  已被替代的决策要弱化显示，但保留可读
- **事件时间线**（竖向）：每条含事件标题、操作人、一句话摘要、事件类型、时间
  不同事件类型需要视觉区分：决策确认、产物提交、任务状态变更、任务阻塞、章程升级

状态：没有决策 / 没有事件 的空状态。

## 补充

这一轮三页都是"信息列表型"页面，难度在于**同质内容的可扫读性**：决策卡、事件行、产物行都要支持快速扫视而不逐字阅读。
