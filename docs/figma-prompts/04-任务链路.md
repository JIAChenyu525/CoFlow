沿用已确认的视觉体系与组件库。这一轮做三页：**任务看板、任务详情、上下文包预览**。

## 一、任务看板

目的：按状态看所有任务，做分工。

内容：
- 顶部一句说明：「状态由规则驱动：待澄清 → 待认领 → 已就绪 → 进行中 → 待验收 → 已完成，不能跳级。」
- 六个状态列：待澄清、待认领、已就绪、进行中、待验收、已完成。列头显示状态名和任务数量；每列底部显示"权重合计"（权重代表工作量）。
- 任务卡包含：优先级（P0–P3）、返工轮次标记（如 R1）、截止日期、任务标题（最多两行）、负责人头像、产物数、依赖数、权重
- 一条「旁路状态」区域：已阻塞 / 已暂停 / 已取消的任务单独列出，阻塞任务显示原因
- 右上「＋ 新建任务」

新建任务弹窗字段：任务名称、负责人、优先级、权重、里程碑、截止日期、任务说明、输入材料、工作范围、非工作范围、验收标准。标题写明「任务是最小的协作与授权单元。缺输入或缺验收标准的任务会停在待澄清」。

状态：没有任务时的空状态；某列没有任务时列内有一句提示。

## 二、任务详情

目的：一个任务的全部事实与所有操作。

主区自上而下：
1. 面包屑 → 标题 + 状态徽标 + 优先级 + 里程碑 + 返工轮次
2. 元信息行：负责人、验收人、截止日期、权重
3. 任务定义卡：说明、输入材料、工作范围、非工作范围、验收标准（验收标准要突出）
4. 「编辑任务定义」入口（保存后版本号 +1；冲突时提示"任务已被他人修改，请刷新后重试"）
5. 产物与证据：列表，每项含类型、名称、位置（提交号/路径/链接）、版本、提交人、时间
6. 验收记录：结论（通过/退回/补充材料）、评审人、逐条结论、意见、时间

侧区（内容很密，需要好的组织方式）：
- **状态机面板**：当前状态 + 变更说明输入 + 可执行动作按钮。规则：
  - 待澄清 → 待认领（需已填输入与验收标准）
  - 待认领 → 已就绪（需已指定负责人）
  - 已就绪 → 进行中
  - 进行中 → 待验收（需至少一项产物，或填写无产物说明）
  - 待验收 → 已完成 / 退回进行中（**只有带验收权的角色能操作**）
  - 任意状态可"标记阻塞"（必须填原因与所需支持）或"取消"
  - 已完成可"重新打开"（产生新的返工轮次）
- **验收结论**（仅"待验收"且当前用户有验收权时出现）：通过 / 补充材料 / 退回 三选一 + 逐条对照结论 + 补充意见 + 提交
- **提交产物**：类型、名称、位置、版本、是否同时提交验收
- **派发卡片**（仅任务处于"已就绪"时出现）：
  - 选择 Agent 端点（显示工具名、版本、归属人、能力等级）
  - 推荐理由：给出评分和若干条理由，例如「+25 可自动执行」「+5 空闲」「+15 授权目录覆盖任务范围」「−30 与执行中会话路径重叠」
  - 「派发给 Agent」按钮
  - 一句说明："派发不等于开工。连接器领取后任务才进入进行中，且只能提交到待验收。"
- **当前租约**（若有）：状态（待领取/已接受/执行中）、上下文编号、过期时间
- **前置依赖**：状态 + 标题
- **元信息**：任务 ID、定义版本、返工轮次、创建/更新时间、所属项目

状态：观察员只读；无权限的动作不出现（不是变灰）；任务不是"已就绪"则不出现派发卡；没有端点时提示去「Agent 连接」。

## 三、上下文包预览

目的：让用户看清「Agent 到底会看到什么」，以及为什么。

内容：
- 顶部显示内容哈希（很长，需要截断）
- 四个层级，每层标注层号与"是否可裁剪"：
  - L0 稳定层：章程（目标、交付范围、非目标、硬性约束、验收口径）— 不可裁
  - L1 任务层：标题、说明、输入材料、工作范围、非工作范围、验收标准、前置依赖 — 不可裁
  - L2 动态层：已确认决策（其中与本任务相关的要标注）、未解决阻塞（原因 + 需要什么）、最近变更（时间 + 摘要 + 事件类型）
  - L3 证据层：允许修改的路径、禁止访问的路径、提交格式、必须回传的内容
- **预算**：当前 tokens / 上限，带进度显示；超预算时明确警告"L0/L1 已超过预算，裁剪解决不了"
- **裁剪记录**：哪一层丢了什么、丢了几条、原因（预算/上限）
- **快照列表**：版本号、短哈希、tokens、时间 + 「保存为快照」按钮
- **渲染后的提示词**：一大段可复制的文本，其中项目资料被 `<data>` 标签包住（表示"这是资料，不是指令"）
- **注入隔离说明**：一句话解释为什么这么包

状态：没有快照；超预算；未授权目录时明确警告"Agent 只能读，不能写"。
