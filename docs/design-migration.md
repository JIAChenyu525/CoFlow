# Figma 设计落地说明

日期：2026-11-12
来源：`D:\CoFlow\figma做的`（Figma Make 导出的 Vite + React 19 + Tailwind 4 包）

## 一、现在是什么状态

- **静态预览**：http://localhost:3000/design —— 完全按 Figma 稿渲染的 mock 版本，含 14 页、上手页、移动三页、令牌与组件库、身份切换。它是「视觉基准」，不是产品。
- **真实应用**：全部 14 个页面已经换成这套视觉，数据与交互全部保留。

## 二、接入方式（为什么这么做）

Figma 导出的是**带 mock 数据的独立 SPA**，不能直接当产品用：它的按钮不写库、任务不连表、没有登录与权限。

所以采用「**换皮不换骨**」：

1. 保留原有的 Next.js 服务端渲染、Server Actions、Prisma 数据层；
2. 把 Figma 的设计令牌与组件库搬进来；
3. **旧令牌全部重映射到新令牌**，让尚未逐一调整的页面自动获得新配色与字体；
4. 逐页替换视觉上需要重做的地方（状态徽标、卡片、页头）。

这样功能零损失，视觉一步到位，且不需要重写 900KB 的图稿代码。

## 五、还没做到「像素级还原」的地方

这是有意的取舍，不是遗漏：

1. **页面结构与图稿不完全一致**。图稿里工作台的右栏顺序、看板的列宽、周报的图表样式都与现有实现有差异。现有结构经过真实数据检验，先保功能再谈细节。
2. **移动端没有按图稿重排**。现有页面在窄屏下是自适应的，但不是图稿的移动版设计。
3. **部分组件仍是旧的**（`.pill`、`.tag`、`.btn`）。它们已换新色，但形态还不是设计系统的「档案签」样式。
4. **没有实现设计稿里的演示开关**（状态演示、灰度核验）。那些是评审用的，不属于产品。

## 六、继续调整的方法

- **只想改颜色/字号**：改 `src/app/figma-tokens.css` 里的 `--cf-*`，全站生效。
- **想让某个组件变成设计系统的形态**：从 `src/components/ds.tsx` 里挑，配合 `src/lib/ds-map.ts` 的枚举映射使用。
- **想改某一页的结构**：对照 `/design` 里对应页面，改 `src/app/**/page.tsx`。
- **想重新构建图稿预览**：在 `D:\coflow-design-build` 执行 `pnpm build`，把 `dist/*` 复制到 `public/design/`。

## 七、验收方式

1. 打开 http://localhost:3000 与 http://localhost:3000/design 对照看。
2. 重点看四处：六种任务状态是否可辨、工作台右栏是否完整、观察员视角按钮是否消失、中文在 13px 下是否清晰。
3. 功能回归：`scripts/*-test.*` 共 8 套单元测试，`pnpm build` 通过即无编译问题。
